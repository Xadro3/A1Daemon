# Claw A1M Linux issue review

Reviewed 19 November 2026. These are upstream issue reports and owner experiences, not a statement that every current installation is affected. A1M findings are kept separate from Claw 7/8 AI+ and A8 reports.

| Issue | Evidence | A1Daemon decision |
| --- | --- | --- |
| Wi-Fi lost after resume; fans/standby drain | [A1M owner report](https://www.reddit.com/r/MSIClaw/comments/1w1bngl/fixing_sleep_and_wifi_issues_inside_steamos_a1m/) and [board-scoped PCI patch submission](https://lists.openwall.net/linux-kernel/2026/10/25/1046) describe sleep/wake failures and the D3cold workaround | Already covered by targeted, reversible workarounds. Keep sleep reliability provisional and validate repeated cycles. |

Include controller mode in resume validation and diagnostic reports. Do not reset USB or replace InputPlumber automatically without reproducing the failure. |

Actual display mode/VRR validation is a separate test; avoid adding a global display workaround based on one report. |
| Long press on Quick Settings restarts the session/device | The same [CachyOS report](https://discuss.cachyos.org/t/i-encountered-two-issues-while-using-the-msi-claw-ultra-5-135h/29967) reports this under Gamescope. | Add short/long/double-press cases to release testing. Keep audio restart as a possible explicit recovery action after reproduction, not an unconditional PipeWire restart on every resume. |

## Release implication

The strongest new candidate is controller recovery after resume. None of the remaining reports justifies broad automatic changes to BIOS settings, PCI power management, graphics-driver binding, audio services or controller ownership on a working Claw. Freeze the first alpha around the tested core and release quality. Keep controller/audio recovery, gyro configuration and display tuning in a tracked follow-up backlog.

One immediate compatibility refinement is justified: support both the installed `go:rgb:joystick_rings` LED name and the current upstream `msi_claw:rgb:joystick_rings` name. Both naming variants are discussed in #722; the latter is also present in the [upstream HID driver](https://github.com/torvalds/linux/blob/master/drivers/hid/hid-msi.c). Do not require users to edit a sysfs path.
